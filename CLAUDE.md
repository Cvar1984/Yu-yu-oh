# Yu-yu-oh: Rust Yu-Gi-Oh! engine, bot and deck builder (LOB / MRD / SRL / PSV + EXTRA)

Full spec: `docs/handoff.md`. This file holds what every session must know.

## Decisions already made (change only with the owner)

- Rust for everything: engine, AI, deck builder, CLI and server. One Cargo workspace, edition 2024.
- Card pool is the 535 cards of the owner's game: the 479 of LOB, MRD, SRL and PSV (Pharaoh's Servant, owner 2026-11-21) plus 56 EXTRA cards the game lists outside those sets (handoff update, 2026-11-20), shipped as JSON. Card id (the official password) is the key in every file.
- Full official chain rules. House rules live in `config/rules.toml`; copy limits live in `data/banlist.json`. Nothing about limits or rules is hard-coded; a rule change must never need a recompile.
- `ygo-engine` knows nothing about AI or UI, does no I/O, and takes randomness only from a seed, so it also builds to WebAssembly.
- Card images are Konami-owned and never committed: `images/` is git-ignored.
- Effects never go into `cards.json`; they are Rust scripts in `ygo-cards`, keyed by card id.

## Conventions

- Keep it simple: no abstraction before the second use, no dependency before it is needed. Empty crates stay empty until their milestone.
- Data formats are strict (`deny_unknown_fields`). A changed bundle must fail loudly, then we adapt the types on purpose.
- Deck legality is a report (`Vec<DeckProblem>`), not an error. Loading failures are `DataError`.
- Paths inside `rules.toml` are relative to `--data-root` (default: the working directory).
- Every behaviour switch in `rules.toml` gets a test that flips it. Every scripted card gets a rulings test.
- CI runs `cargo fmt --check`, `cargo clippy --workspace --all-targets` with `-D warnings`, and `cargo test --workspace`. Run `scripts/check.sh` before every commit; it fails on the first problem.
- The workflow lives in `docs/ci-workflow.yml` until someone with the GitHub `workflow` scope moves it to `.github/workflows/ci.yml`; sessions here cannot push workflow files.

## Engine notes (ygo-engine)

- `Game` is a struct, not a trait; `Shared` (rules + `CardPool`) is built once and held by `Arc`, so a game clone is flat vectors plus a pointer bump. No `Rc`, no `RefCell`, no lifetimes in state.
- Every choice is an `Action`; `legal_actions` enumerates all of them (tribute combinations included) and `apply` refuses anything else. Phases without a decision advance automatically.
- Any Main Deck monster can be Normal Summoned unless its script carries `Tag::CannotNormalSummon`. Every non-Normal card has a script; `crates/ygo-cards/tests/registry.rs` fails if one is missing.
- Work that waits on the players sits on a stack of `Pending` items: response windows, a declared summon before its negation window closes, a declared attack, the damage calculation, a chain to resolve. `advance` works the top item and stops only when a player has a real choice; a window whose player has nothing to activate is passed automatically.
- Between a summon's declaration and its success only speed-3 effects (Counter Traps) may start a chain; other Traps wait for the summon-success window.
- An attack replays (`DecisionKind::Replay`: any legal target, the same one included, or stop) when its target left the field or the defender's number of monsters changed since the declaration (`Pending::DamageStep.monsters`): Scapegoat stops a direct attack.
- Windows open after Sets and position changes, at summon declaration and success, at attack declaration, inside the Damage Step before damage calculation, after battle, after each chain link and after a chain resolves, and at the Standby, Battle-start, Battle-end and End Phases. Trigger and Flip effects are collected when a window opens, in SEGOC order.
- `scripts/check.sh` must pass before every commit; `cargo test --no-fail-fast` shows every failing binary at once.
- `GameSetup.shuffle = false` keeps decks in listed order for scenario tests; `tests/common/mod.rs` has `stacked`, `shared_with` (rules with one change) and known card ids.
- Tokens (Scapegoat): `special_summon_token` reuses a gone Token instance or appends one, so `instances()` can grow during a game; a Token sent anywhere off the field goes to `Location::Gone` instead (`Event::TokenRemoved`). Code that builds decks from the pool uses `CardStats::is_main_deck`.
- Instance ids are assigned in a seeded random order so an id never reveals a face-down card's identity. Bots get a `PlayerView` (the decider's observation and legal actions); the real game stays private. `PlayerView::sample(seed)` returns a whole game that looks identical to the decider, with every card they cannot see redealt among its owner's hidden places and a fresh RNG; `tests/view.rs` in `ygo-ai` checks this at every decision of random games.
- Modern-rules state: a Set completes with no negation window; Gate Guardian, the Moths and the Toons use summon procedures (`Action::ProcedureSummon`, `SummonKind::Procedure`, with a summon-negation window); each instance knows whether it was properly summoned (`special_summonable`, `special_summon_properly`, `room_after_leaving`); a `ChainLink` records `card_activation` and the cost's `value`; Field Spells can be Set; optional "When" triggers set `misses_timing`; once-per-turn names and name locks live in `PlayerState` (`use_name_once`, `lock_name_this_turn`) and clear at turn start. `tests/modern_rules.rs` and `tests/card_fixes.rs` in `ygo-cards` show each rule with real cards.
- Speed baseline (after the last EXTRA scripts, 2026-11-24, same setup): 1,501 to 1,701 random games/s and Beatdown 3,035 to 4,815, within this container's noise of the previous build run alongside (1,632 to 1,812 and 3,280 to 5,229); callgrind counts 1.1% more instructions for the same 300 games. Wall-clock runs here vary by 15% between identical runs: compare instruction counts (`valgrind --tool=callgrind`) for small changes. Before (after the PSV scripts, 2026-11-21, release, one core of this cloud container, enemy decks e1-e2, e3-e4, e5-e6): 1,512 to 1,896 random games/s, 310,000 to 413,000 actions/s; the Beatdown bot against itself 2,974 to 4,013 games/s. The rarely used hooks (negation, Type changes, immunity, `forbid`) cost nothing in a game whose cards lack them (`Game.hooks`). After the modern-rules work it was 1,215 to 1,812 random games/s and Beatdown 2,860. M4 was 1,870 to 2,580 games/s (350,000 to 400,000 actions/s) and Beatdown 3,777; the drop comes from the new name, procedure and proper-summon checks. M3 was 1,700 to 2,200, M2 2,600 to 3,500 and M1 7,300. Profiling (`valgrind --tool=callgrind` on `ygo sim`) at M2 showed a third of the time in `observe` and a fifth in allocation; M3 adds continuous-hook scans on every attack, summon and Graveyard move. An observation buffer reused across decisions, and caching the face-up continuous effects per state, are the next wins. Re-measure with `ygo sim` after engine changes and keep the numbers here current.

## Records, play and bots (ygo-engine, ygo-ai, ygo-cli)

- A game record is JSON Lines: a header with the full `Rules`, the `GameSetup` and player labels, one line per action, then the result. It replays under its own rules, so `rules.toml` changes never break old records. `GameRecord::note` goes before `apply`.
- Bots implement `ygo_ai::Player`: `choose(&PlayerView) -> Action`; they see only the observation and samples. Owner (2026-11-25): the trained network is the bot; the heuristic, lookahead and playout-search bots, their styles and card values (`config/styles.toml`, `config/card_values.toml`), `ygo audit`, `ygo distill` and the tools that drove them were removed (their last results are in `docs/m6-plan.md`; earlier milestone reports describe them as they were). The random bot stays as the floor and the fuzzing driver.
- `NeuralPlayer` (`ygo_ai::neural`) plays the network's most likely action (or samples at a temperature). `MctsPlayer` (`ygo_ai::mcts`) is the network-guided search, AlphaZero on single-observer information-set MCTS: per iteration a new sample of the hidden cards, one shared tree, PUCT at every node (`exploration` 0.75) with the network's priors, a position the tree has not reached judged by the network's value, no playouts. Its `MctsSettings` (iterations, default 100, time limit, exploration) are bot settings, not rules; the browser never sets a time limit, so a resumed game replays the bot's choices exactly.
- `ygo_cli::bots::Bots` turns `network` (the shipped network, `--network`, default `data/networks/best.bpk`; the default opponent), `network-search` (it guiding the search), `random`, `neural:<checkpoint>` or `neural-search:<checkpoint>` into a player for `play` and `sim`; the network names need the `neural` feature. `data/networks/best.bpk` is replaced only by a checkpoint that passes the M6 gate. Evaluate any bot change with `ygo sim` (2,000 games, 95% interval) and record the numbers.
- `ygo play` and `ygo sim` refuse a deck that fails the check-deck report (cards, ban list, deck rules; not the collection).
- The browser game sends JSON commands to `ygo_wasm::Host::handle` (tests call it natively); its view is built from the human's observation only, so hidden cards never reach the page. A game resumes from its seed and the human's choices. The published page ships a card file without images or print records, and no Konami art. It ships the network (`data/network.bpk`), handed to the engine with `ygo_set_network` before `init`; the page answers the wasm-bindgen imports burn's dependencies link (random bytes, the panic message; the rest are stubs that fail by name). `wasm32-unknown-unknown` has no clock: read `Instant` only when a time limit is set.
- `PlaySession` and `ReplaySession` hold the logic; `tui.rs` only draws and reads keys, so tests drive sessions and check screens with ratatui's `TestBackend`. Anything shown to a player is rendered from that player's observation (`describe.rs`).

## Writing a card script (ygo-cards)

- One `CardScript` per card id, registered in the module for its group: `spells`, `traps`, `monsters`, `continuous` (the 30 key cards), `tables` (table-driven Equips, Field Spells and boosters), `oneshot`, `reveal`, `fusion`, `ritual`, `monsters_a`, `monsters_b`, `flips`, `toons`, `remaining`, and `extra_monsters`, `extra_spells`, `extra_traps` for the EXTRA cards (`tests/extra.rs`), and `psv_monsters`, `psv_spells`, `psv_traps` for Pharaoh's Servant (`tests/psv_*.rs`, helpers in `tests/psv_common`, also used by `tests/extra_2.rs` for the last EXTRA cards). Function pointers only, no closures capturing state; everything an effect needs is in `EffectCtx` or read back from the `Game`.
- `Effect::activate(speed, resolve)` for Spells and Traps, `Effect::trigger(mandatory, resolve)` for triggers, `Effect::flip(resolve)` for FLIP effects, `Effect::continuous()` with `modify` or `restrict` for static effects. Override `timing`, `targets`, `cost_choices` and `cost` as needed; set `damage_step: true` for effects that may start inside the Damage Step.
- `timing` sees the open `Window` (its kind and events); `targets` and `cost_choices` enumerate every legal set and the engine turns them into `Activate` actions. A resolution that needs a pick returns `Flow::Choose` (cards) or `Flow::Ask` (labelled options) with a continuation; `ChooseBy` and `AskBy` let the other player answer. A trigger that needs facts from its window (Kotodama, Trap Hole) must capture them in `targets`, because the window is gone by resolution.
- Continuous hooks besides `modify` and `restrict`: `on_attack` (attack costs), `attack_lock`, `on_battle_damage`, `replace_battle_destruction`, `lock_position`, `pierce`, and (PSV) `negate` (Jinzo, Imperial Order: `Game::negated`; a negated card's continuous effects, tags, triggers and activations are off, and its chain link resolves without effect), `forbid` (Prohibition: an action is illegal), `race` (DNA Surgery: scripts read Types with `g.race`, never `stats().race`), `spell_immune` and `unattackable` (the Umi monsters). `restrict` means "cannot declare an attack"; a card whose text says "cannot attack" also calls `cancel_attack` to stop an attack already declared (Shadow Spell, Spellbinding Circle). Tags: `CannotNormalSummon`, `DirectAttacker`, `Toon`, `RevealHands`, `RevealOpponentHand` (The Eye of Truth), `BanishInsteadOfGraveyard`, `HandPlayToll`, `StaysOnField`, `ControlWhileEquipped` (Snatch Steal), `StaysWithoutTarget` (Spellbinding Circle), `OnlyByProcedure` (the Moths: never Special Summoned by another effect), `RevealTurnPlayerHand` (Respect Play), `SecondAttack` (Hayabusa Knight), `StatsSetOrScaled` (its ATK/DEF changes set, swap or multiply: Reverse Trap leaves them), `NoFaceDownMonsters` (Light of Intervention), `NoTributeSummon` (Sheep Token), the Exodia tags. A face-up Spell or Trap's `EffectKind::Quick` effect may be activated (Ultimate Offering). Effect flags: `once_per_turn`, `damage_step`, `in_standby`, `misses_timing`. `EffectKind::Procedure` is a summon procedure, not an effect: it never starts a chain.
- Modern text rules for scripts: when the text names no position for a Special Summon, ask it (`positions.rs`: `face_up`, `attack_or_set`); compare current ATK (`g.atk`), never printed ATK; LP costs use `can_pay_lp` (paying all your LP is legal); "Special Summon" effects check `special_summonable` and use `special_summon_properly` only for the card's own proper summon; a cost that must hand a number to the resolution sets `ctx.value`. Choices the text makes on resolution (Polymerization, The Cheerful Coffin) are `Flow::Choose`, not targets.
- A card's `counter` survives leaving the field and resets when it enters the field again. `CardStats.flip` marks Flip monsters; `PlayerState.monsters_to_graveyard` counts this turn's monsters sent from a player's field to their Graveyard (Last Will). `CardInstance.attacks_this_turn` counts attacks (a count since Hayabusa Knight) and `destroyed_by_battle` names the monster that destroyed a card and the turn (Sword Hunter, Vampire Baby). Off-field cards stay with their owner except a card put face-up into the opponent's Deck (Parasite Paracide) or a borrowed one (Graverobber); `check_invariants` allows exactly those.
- Engine operations for scripts live in `ops.rs` (and a few in `chain.rs` and `battle.rs`): draw, destroy, discard, mill, mill_by, banish, tribute, special_summon, fusion_summon, ritual_summon, change_control, swap_control, set_position, flip_face_up, equip, attach, absorb_as_equip, gain_lp, pay_lp, take_damage, add_to_hand, return_to_deck, place_on_top_of_deck, reorder_top, shuffle_deck, reveal, coin, random_index, modify_until_end_phase, modify_during_damage_calculation, destroy_at_end_of_turn, forbid_attacks_until, grant_extra_battle_phase, end_battle_phase, shield_until_chain_ends, retarget, set_counter, negate_activation, negate_summon, prevent_battle_damage, special_summon_properly, forbid_position_change_this_turn, use_name_once, lock_name_this_turn, clear_marks, look_at (a private look: `Event::LookedAt` carries the card ids, and only the looker's log names them), cancel_attack, shield_from_battle_this_turn (Waboku), set_from_hand, and from PSV turn_face_up_quietly (no FLIP effect), skip_next_draw, skip_next_standby, skip_next_turn, lock_position_until, forbid_spells_and_traps_until, negate_until_end_of_turn, put_face_up_in_deck, lock_zone, banish_face_down, return_to_hand_after_standbys, banish_until_next_standby, borrow_to_hand, set_as_monster, mark_hat, shuffle_set_monsters, and from the last EXTRA batch change_race_until_end_phase, retarget_attack, special_summon_token, normal_summon_by_effect (lingering `StatChangesReversed`, `MustTribute`, `NoBattlePhase` and `NoSummons` are added with `add_lingering`); and queries such as atk, def, race, negated, zone_locked, is_hat, unaffected_by_spells, cannot_be_attacked, pierces, hand_revealed, on_field, spell_targetable, attack_targets, face_down_forbidden, must_tribute, summons_locked, special_summonable, room_after_leaving, can_pay_lp, name_used, marked_by, pending_summon, last_link, current_attack, window, top_of_deck, hands_revealed.
- Every scripted card gets a rulings test in `crates/ygo-cards/tests`, built on `ygo_engine::testing` (stacked decks, `play`, `next_turn`, `pass_all`, `with_rules`).

## Data formats (from the data bundle)

`cards.json` carries `"schema_version": 2`, every other file `1`; `ygo-data` rejects any other version (`CARDS_SCHEMA_VERSION`, `SCHEMA_VERSION`). `name` fields next to ids are for humans and are never checked.

- `cards.json`: `{ schema_version, source, sets, count, note, cards: [Card] }`. `count` must equal the array length. Each card has `in_game_index` (LOB, MRD, SRL, PSV or EXTRA: the list it sits under in the owner's game); EXTRA printings add `set_name`. `type` uses YGOPRODeck spelling; the sets contain Normal, Effect, Flip Effect, Toon, Fusion, Ritual and Ritual Effect Monsters plus Spell and Trap Cards. Spells and Traps have `null` level, ATK, DEF and attribute, and `race` holds their subtype.
- `tokens.json` (owner, 2026-11-23): `{ schema_version, source, count, note, tokens: [ { id, name, made_by, race, attribute, level, atk, def } ] }`. Tokens join the engine's pool (`CardStats.token`) but never `CardDb`'s cards, decks or collections.
- `banlist.json`: `{ schema_version, name, updated, default_limit, note, limits: [ { id, name, limit } ] }`. `default_limit` is informational and must equal `deck.default_copy_limit` in `rules.toml`; every listed limit must be below it.
- `collection.json`, `collection_save_b.json`: `{ schema_version, owner, read_from, totals: { set: "owned/total" }, unique, copies, cards: [ { id, name, copies } ] }`; `unique` and `copies` are checked against the list.
- `decks/*.json`: `{ schema_version, name, for, notes, main: [ { id, name, count } ], extra: [ ... ] }`. `for` is `enemy`, `save A` or `save B`; every deck has one, and an owned deck must fit that save's collection (`tests/real_data.rs`). Copy limits count Main and Extra Deck together.
- `tools/refresh_cards.py [root]` rebuilds `cards.json` and fetches missing images from YGOPRODeck; it never touches the ban list. `reference/python_prototype/` is the simplified Python simulator, reference only.

## Owner's answers (2026-11-16, updated 2026-11-20)

- 2026-11-18: the basic rules and every card follow the modern official rules and modern card text (2026-11-20: "modern, retro classic": modern rules on the classic card pool, with the classic exceptions listed here). Revival follows the card text: Monster Reborn revives almost anything, except monsters that must first be summoned a certain way and were not (Ritual, Fusion, Toons, Gate Guardian, Harpie Lady Sisters, Wall Shadow), and monsters that "can only be Special Summoned" one way (Larvae Moth, Great Moth: `Tag::OnlyByProcedure`, never revived).
- The browser board follows the owner's playmat: per side, Field | 5 Monster zones | Graveyard above Extra Deck | 5 Spell & Trap zones | Deck.

- Hand: no cap during a turn (Pot of Greed may push it past 6). In your Draw Phase, after drawing, discard down to 6 (`hand_limit_check = "after_draw"`, owner 2026-11-20, replacing the End Phase check of 2026-11-18; `"end_phase"` is the modern rule). The turn has six phases: Draw, Standby, Main 1, Battle, Main 2, End; Traps are Set and Flip Summons made in a Main Phase, attacks in the Battle Phase, and Special and Tribute Summons are allowed in Main Phase 2 too.
- Spells and Traps per turn: no count. The only limit is the 5 zones (`spell_trap_zones`); the earlier `spell_trap_plays_per_turn` key was removed.
- A Trap cannot be activated in the turn it was Set (`trap_activation_turn_set = false`, modern; `true` was the earlier house rule).
- Spells may target a monster Set this turn (`spell_target_monster_set_this_turn = true`, modern; `false` was the earlier house rule). Normal Summons and Sets are allowed in Main Phase 2 (`summon_in_main_phase_2 = true`).
- Field Spells: see 2026-11-20 above (`field_spells_on_field = 1`, classic shared; `2` is modern, one per player).
- Flip and Special Summons do not count toward a per-turn limit, but this may change, so both stay config keys.
- Fusion and Ritual Summons are allowed (`fusion_summons`, `ritual_summons`).
- Card text: support both modern and original 2002 text. `cards.json` holds only modern text; the original text needs a second data source, keyed by id, before `text_version = "original_2002"` can do anything. Effect scripts whose rulings differ by printing (Sangan, Witch of the Black Forest) must branch on this key.
